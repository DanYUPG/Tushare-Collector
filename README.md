# Tushare Collector

**在自己的电脑上配置 Tushare 股票数据采集，维护本地数据，再按需查询和导出。**

程序提供独立网页界面。配置、数据需求和运行记录保存在 SQLite，采集结果写入指定 Raw 目录，整理后的本地仓库使用 Parquet。普通使用只需启动一个 Python 服务，不需要安装 Node.js 或单独启动前端。

> 本项目是本地单用户数据工具，不是交易系统，也不是 Tushare 官方产品。仓库不包含 Token、账号权限或下载好的行情。请使用自己的账号，并遵守供应商的数据使用及再分发条款。

## 安装和启动

### 准备环境

安装 [Git](https://git-scm.com/downloads) 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)，并准备自己的 [Tushare Pro](https://tushare.pro/) Token。

程序需要 Python 3.11+，项目默认使用 3.12；缺少对应 Python 时，uv 可按项目设置下载。首次安装需要联网。

| 系统 | 注意事项 |
|---|---|
| Windows 10 / 11 | 使用 **x64 Python**；当前锁定依赖不提供原生 ARM64、32 位 Python 的开箱支持。不要求 WSL |
| macOS / Linux | 使用本机 Python 环境和有写权限的本地目录 |
| 所有系统 | 建议使用本地磁盘，不把 NAS、网络共享或云同步目录作为运行中的数据目录 |

各平台自动检查的实际结果见 [GitHub Actions](https://github.com/DanYUPG/Tushare-Collector/actions/workflows/tests.yml)。未完成的检查不代表已验证；桌面目录选择对话框仍取决于本机图形环境。

### 下载并运行

在终端执行；以下四行也可以直接在 Windows PowerShell 中执行：

```bash
git clone https://github.com/DanYUPG/Tushare-Collector.git
cd Tushare-Collector
uv sync --locked
uv run --locked tushare-collector
```

浏览器打开 http://127.0.0.1:7110/。

终端需要保持运行。停止时按 `Ctrl+C`，等待当前请求处理结束。**同一个控制目录只启动一个实例，不要开放到公网。**

### 指定数据目录或端口

不指定时，个人数据保存在项目的 `data/` 中。建议首次使用就选定长期使用的数据目录，避免日后移动路径。

macOS / Linux：

```bash
uv run --locked tushare-collector --port 7111 --data-dir "$HOME/TushareData"
```

Windows PowerShell：

```powershell
uv run --locked tushare-collector --port 7111 --data-dir 'C:\TushareData'
```

此时访问 `http://127.0.0.1:7111/`。请选择自己有写权限的路径；Windows 尽量使用短路径。

**后续启动继续使用同一个 `--data-dir`。** 换一个目录会使用另一套配置和数据库，不会自动搬迁旧数据或凭证。

## 第一次采集

建议先选一个有权限的接口和较小日期范围，确认结果后再扩大。

1. 打开“**工具与设置 → 接口凭证**”，填写自己的 Token 并保存。默认只在当前程序进程中使用。
2. 打开“**我的数据 → 新增数据需求**”，填写名称，按分类或 API 名查找数据。**新增需求不默认选择任何接口。**
3. 选择接口，核对分类参数、历史起点、截止日和“更新与请求预算”。第一次先不要启用自动维护。
4. 点击“**仅保存需求（不联网）**”。保存配置不会向 Tushare 发送请求。
5. 打开需求详情，点击“**立即同步**”，核对范围并授权本次联网。
6. 在需求详情或“**运行记录**”查看进度。成功发布后，进入“**查询 / 导出**”查看本地数据。

程序可能先准备股票列表、交易日历或板块代码池。这些依赖请求也计入本轮预算，并不表示额外交付了这些数据集。

### 是否记住 Token

不希望每次重启都输入时，可以勾选“**记住 Token**”。

> **这是明文保存，不是加密。** 文件位于 `<控制目录>/.tushare-token`。macOS / Linux 使用仅当前用户读写的权限；Windows 使用当前用户专属 ACL。能读取文件的人、同账户恶意程序、管理员，以及获得备份或云同步副本的人都可能拿到 Token。程序内也会显示该风险。不要分享凭证文件或整个个人数据目录。

Windows 记住凭证需要支持 ACL 的本地文件系统，例如 NTFS；不支持的文件系统会明确报错，不会降低保护后继续保存。

不勾选“记住 Token”而保存新 Token，会移除之前记住的文件，仅本次进程有效。“清除本机凭证”同时删除本地文件并清空当前进程凭证，不删除数据。

也可在启动环境设置 `TUSHARE_TOKEN`。非空环境变量在启动时优先于本地文件；若要彻底清除凭证，还需要移除该环境变量，否则重启会再次加载。

## 管理数据需求和自动维护

“**我的数据**”适合长期维护数据。同一需求可包含多个接口，各接口保留自己的分类参数和日期规则，不统一当作日线处理。

| 设置 | 如何选择 |
|---|---|
| 历史起点 | 从实际需要的日期开始，避免首次就请求几十年数据 |
| 固定截止日 | 留空时每轮滚动到北京时间昨天；当前快照不使用历史截止日 |
| 近期修订回查 | 重查近期范围，以发现可能修订；不会自动发现窗口外的全部变化 |
| 每日尝试时间 | 使用北京时间，只有服务运行时才会执行 |
| 请求速率 | 仍受程序全局限制和具体接口限制约束 |
| 每轮请求上限 | 包含依赖、失败请求和重试；重启不会让当前作业的已用预算归零 |

需要自动更新时，勾选“**启用自动维护**”，阅读并单独授权，再保存。**首次启用会立即尝试**，以后按配置时间尝试。关闭浏览器不影响仍在运行的服务；停止服务、电脑关机或休眠期间不能执行。服务恢复后会合并错过的触发，不逐次补跑每个定时时间点。

“立即同步”只授权本次作业，不会顺带开启每日维护。同一数据集只允许一个启用的维护需求。

修改范围或参数前，先暂停当前需求；修改后重新核对并保存。暂停不会删除已采集数据，缩小需求范围也不会自动删除范围外历史数据。接口规则或字段契约变化时，程序会停止自动执行，等待核查和重新确认。

实时接口每次只采集当前一轮，不持续盯盘；部分复权接口每轮需要整段重拉。请结合页面显示的接口规则评估请求量。

## 浏览与导出

### 查询本地仓库

从需求详情进入“**查询 / 导出**”，或打开“**数据浏览**”切换数据集。

可以按接口支持的日期、股票或板块代码、字段筛选。存在多个请求变体时，先选择变体，避免混合不同频度、分类或复权口径。当前快照接口不支持用日期还原历史快照。

查询和翻页只读本地文件，不调用 Tushare。页面显示的日期数、行数和最新记录日期是本地数据摘要，**不等于全市场完整性证明**。

### 导出供分析使用的数据

在仓库中选择范围和字段后打开导出，指定绝对目标目录。可选：

| 文件组织 | 适合用途 |
|---|---|
| 保留源分区 | 保留多文件，按清单读取 |
| 合并单文件 | 将所选结果写成一个 Parquet 文件 |
| 按字段值拆分 | 例如每只股票一份，或每个交易日一份 |

可以设置排序；导出仍保留必要的定位字段，不自动去重。按字段拆分最多 10,000 组，超限时缩小范围后重试。

每次生成独立的 `tushare_warehouse_bundles/` 导出包，包含 Parquet、`manifest.json` 和来源快照清单，不覆盖仓库或旧导出。排序和合并需要额外临时磁盘空间。

### 查看或导出原始归档

在“**高级工具 → 原始归档**”中，可按接口、Raw 目录、请求条件或状态查找，打开单个采集切片，检查实际参数、字段和数据。

原始归档导出提供“原始归档”和“后处理友好”两种布局，均复制完整源文件，不受阅读页搜索、显示字段或分页影响。整次运行只导出成功切片；失败但有可读数据的切片可单独导出，仍会保留失败标记。

“后处理友好”按接口入口、请求选项和字段结构分组。新包使用短标识命名，从 `manifest.json` 的 `groups[].data_directory` 定位数据目录；`d/` 放数据，`m/` 放元数据。完整请求条件和来源标识保留在清单中。**只整理副本，不合并、不去重、不转换 JSON。** 不要根据文件名猜测数据覆盖或直接混读不同分组。

## 单次查询与自定义 API

不需要长期维护时，可以使用“**高级工具**”：

| 入口 | 操作方式 |
|---|---|
| 预置采集 → 查询一次 | 选择接口，填写参数和字段，先检查请求，再明确确认查询；结果可直接预览 |
| 预置采集 → 首次采集 / 更新数据 | 使用已有采集规则规划历史、更新或未完成范围；缺依赖时先单独确认准备依赖 |
| 自定义 API | 选择接口，配置请求参数、字段、切片和绝对 Raw 目录，检查计划后确认启动 |

单次查询可能返回很多行，不是供应商端只取预览页；建议先限定股票和日期。预览翻页不会重新查询供应商。两个 `pro_bar` 派生入口不在“查询一次”中提供。

自定义 API 的 SDK / HTTP、JSON 参数、超时和重试位于高级设置。自然日切片不会自动过滤非交易日；空响应策略需要符合接口含义。修改参数后必须重新检查，不能沿用旧确认。

常用配置可保存为任务，再组合批量执行。保存任务、任务组或检查计划都不会自行联网；高级任务不会因为保存配置而变成定时任务，长期调度请使用“我的数据”。

自定义采集和即时查询会保留 Raw，但不会自动变成托管数据需求或自动导入预置仓库。

## 查看运行和处理失败

“**运行记录**”保留已确认范围、执行进度、成功与失败切片、实际参数和错误。成功归档不会因其他切片失败而被删除。

| 情况 | 建议处理 |
|---|---|
| 权限不足、积分不足、独立权限未开通 | 核对账号和官方文档，不要反复盲试 |
| 频率或日额度限制 | 降低速率或等待额度恢复；增加线程不会增加账号额度 |
| 达到行数上限、疑似截断 | 使用页面提供的拆分检查，或缩小请求范围后重新确认；不要调高检查阈值来假装成功 |
| 网络暂错 | 查看是否已用完有限重试，再按页面恢复入口处理未完成部分 |
| 字段、类型、哈希或写后回读失败 | 保留证据并核查；失败不会替换原已发布快照 |
| 计划失效、配置已变化 | 重新检查计划并确认，不重复提交旧确认 |

普通手工任务中断后不会自动续跑，需在结果中核查并恢复；仍获授权、未暂停的数据需求作业可在重启后按已冻结范围继续。取消和正常停止会等待已发出的请求返回，不会中途丢弃可保存的响应。

在“工具与设置”可选择 1–16 个采集线程。修改对下一个运行生效；所有线程共享限流和额度，不建议为追求速度直接拉满。

## 数据保存在哪里

`--data-dir` 指定的是**控制目录**，默认是项目下的 `data/`：

| 位置 | 内容 |
|---|---|
| `collector.sqlite3` | 配置、需求、运行、来源登记及清理记录 |
| `.tushare-token` | 可选的本机明文 Token |
| `raw/` | 默认原始采集归档位置 |
| `warehouse/` | 已发布的本地仓库和历史快照 |
| `exports/` | 默认导出位置；也可以另选目标目录 |

采集 Raw 目录可在对应采集设置或自定义任务中单独指定。已有需求绑定其保存时的目录与规则；改目录后应核查并重新保存需求，不会自动搬迁旧数据。

SDK 模式的 Raw 是 SDK 返回表格的 Parquet 快照，**不是 HTTP 原文**；HTTP 模式保存原始响应字节。仓库是适配后的本地查询数据，导出是另外生成的副本，三者不能互相当作完整备份。

新临时文件、请求分区和后处理导出使用较短的内部名称；完整逻辑 ID 与校验哈希不截断。已有文件不自动重命名，无需手工修改旧目录。直接读取仓库时以当前快照清单列出的文件为准，不要扫描并拼接全部历史快照，否则可能重复读入修订版本。

**不要手工移动、改名或清空程序管理的数据文件。** 数据库中含绝对路径引用，换目录或换机器不等于完成迁移；当前没有通用的一键迁移工具。

## 释放存储空间

打开“**我的数据 → 更多 → 存储管理**”。

自动释放默认关闭。需要手动释放时，先检查候选文件和预计空间，核对后单独授权永久删除。默认快速检查不重算全部数据内容哈希；更重视内容校验时选择深度检查，耗时会增加。

自动策略目前**仅限 `daily / daily_basic / adj_factor`**，且只处理通过全字段保留证明、写后回读等安全检查的当前快照来源。默认保留最近 7 天归档，按采集归档时间而不是业务日期计算。其他接口、规划依赖、未知文件和不符合条件的旧来源不会因此自动删除。

启用自动释放会立即尝试，以后在配置时间检查，仅服务运行时有效。它不需要 Token，与采集联网授权分开。暂停会阻止后续批次，不恢复已删除文件。

> **释放不可撤销，也不等于无损归档。** 删除 Raw 后不能保证重建供应商原响应或重新提取其他字段。请先备份。已发布仓库和导出副本不会被该策略删除；检查完成也不表示所有 Raw 都已清空。

原始归档列表的“删除归档”是另一种操作，只删除明确确认的文件；可能使对应范围需要重新采集。不要用它替代“已入仓中间文件释放”。

## 更新与备份

### 备份

先暂停自动维护和存储释放，等待作业结束，再按 `Ctrl+C` 正常停止服务。

备份完整控制目录，以及所有单独指定的 Raw 和需要保留的导出目录。**不要在服务写入 SQLite 时只复制主数据库文件。** Git 不会替你备份个人数据。

备份含 `.tushare-token` 时按敏感数据保管；也可排除该文件，恢复后重新配置 Token。同机恢复时保持原目录路径；跨路径或跨机器恢复需要额外处理绝对路径引用。

### 更新

保留升级前备份。确认代码目录没有自己尚未提交的修改后执行：

```bash
git pull --ff-only
uv sync --locked
uv run --locked tushare-collector
```

平时使用自定义端口或数据目录时，最后一行继续带上原来的 `--port` 和 `--data-dir`。普通使用不需要重新安装前端依赖或自行构建网页。

旧版本不一定能安全读取新版本修改后的数据库，不要只回退代码而忽略数据备份。

## 常见问题

| 问题 | 处理方式 |
|---|---|
| 找不到 `uv` 或 `git` | 完成安装后重新打开终端，确认命令已加入 PATH |
| 浏览器无法连接 | 检查终端服务是否仍在运行，以及浏览器端口是否与启动参数一致 |
| 端口被占用 | 使用 `--port 7111` 等空闲端口，再访问对应地址 |
| 提示已有服务使用控制目录 | 回到原实例；确认并正常停止重复实例，不要通过删锁文件绕过保护 |
| 重启后配置或数据“消失” | 检查是否用了不同的 `--data-dir`；换目录不会自动读取旧数据库 |
| Token 已配置但无法采集 | 已配置不等于验证了权限；查看具体错误和接口授权要求 |
| 选择目录按钮报错 | macOS 使用系统对话框；Windows / Linux 依赖 Tk 和桌面环境。可直接手工输入绝对路径 |
| Windows 路径太长 | 优先缩短控制、Raw 或导出根目录；确需长路径时按系统管理要求启用长路径支持并重启程序 |
| Windows 文件被占用或发布失败 | 关闭正在打开文件的程序，检查目录权限、同步软件及安全软件占用，再按错误恢复；不要关闭必要的系统保护 |
| Windows 记住 Token 失败 | 使用当前用户可写、支持 ACL 的本地目录；不要把凭证权限开放给其他用户来绕过检查 |
| 服务停止后没有自动更新 | 维护任务不是系统定时服务，需要程序持续运行；电脑休眠也会暂停执行 |
| 运行成功但没有记录 | 成功空响应按接口规则处理，不证明账号有全部权限、当天休市或数据完整 |
| 为什么仓库仍占空间 | Raw 释放不删除仓库快照和导出；当前没有历史快照自动回收功能 |

Windows 文件发布已做平台适配，但不具备这里 POSIX 目录同步所提供的相同断电持久性保证。不要依赖一次成功提示替代备份。

## 支持范围与使用边界

目录依据 [Tushare 股票数据](https://tushare.pro/document/2?doc_id=14)组织，当前适配 **102 个股票接口入口**：

| 分类 | 入口数 |
|---|---:|
| 基础数据 | 13 |
| 行情数据 | 17 |
| 财务数据 | 10 |
| 参考数据 | 15 |
| 特色数据 | 11 |
| 两融及转融通 | 7 |
