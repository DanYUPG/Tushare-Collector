# Tushare Collector

**面向个人研究的 Tushare 本地股票数据工作台。声明需要的数据，维护自己的本地仓库，再按需查询和导出。**

独立 Python 服务与 Web 界面，使用 SQLite 保存配置、任务和执行状态，使用 Parquet 保存本地数据。默认通过官方 Tushare SDK 采集，也支持高级任务直接调用 HTTP；React 前端由同一 Python 服务托管，普通使用不需要安装 Node.js 或单独运行前端服务。

> **使用边界**：这是本地单用户工作台，不是交易系统、回测引擎或公开数据服务。仓库不包含 Token、账号权限或下载好的行情。所有使用者需要配置自己的 Tushare Token，并自行确认数据使用和再分发权限。

## 功能概览

| 能力 | 说明 |
|---|---|
| 声明数据需求 | 按分类或 API 搜索接口，配置历史范围、参数、请求预算和每日维护时间 |
| 股票目录适配 | 当前内置 102 个股票接口入口，均有采集、入仓、查询和导出适配 |
| 本地仓库 | 原子发布不可变快照，保留来源、字段类型、哈希和写后回读校验信息 |
| 查询与导出 | 按数据集、日期、代码、字段和请求变体筛选，导出 Parquet Bundle |
| 文件组织 | 保留源分区、合并单文件、按字段值拆分；支持排序并保留定位字段 |
| 可恢复作业 | SQLite 持久化需求、计划、切片、尝试和失败原因，支持按规则恢复或补采 |
| 授权与限流 | 联网和删除分别确认；共享限流、请求预算和部分接口滚动日额度 |
| 存储管理 | 检查已入仓来源后按策略释放中间文件，默认关闭自动释放 |

102 个入口包含旧版、停更及两个官方 `pro_bar` 派生入口，**不等于 102 个独立 HTTP API，也不代表账号有全部权限或数据已完整下载**。不包含基金、ETF、期货、期权或港美股专题。

## 快速开始

### 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | macOS 为当前使用环境；核心依赖 POSIX 文件锁和文件权限，Linux 需在目标环境自行验证 |
| Python | 3.11+；项目 `.python-version` 默认选择 3.12 |
| Python 包管理 | [uv](https://docs.astral.sh/uv/getting-started/installation/) |
| Node.js | 仅开发或重新构建前端时需要，建议 22.12+ |
| Tushare | 自有 Pro Token，以及所选接口所需的积分或独立授权 |

当前不支持原生 Windows 直接运行：代码使用 `fcntl` 等 POSIX 能力。WSL 可作为候选运行环境，但不宣称已完成验证。原生目录选择器目前仅适配 macOS，其他环境可手工输入绝对路径。

### 下载与启动

```bash
git clone https://github.com/DanYUPG/Tushare-Collector.git
cd Tushare-Collector
uv sync --locked
uv run --locked tushare-collector
```

访问 **http://127.0.0.1:7110/**。仓库包含已构建的前端静态资源，运行上述命令即可使用。第一次安装依赖需要网络。

服务在当前终端前台运行，按 `Ctrl+C` 正常停止，并等待正在处理的请求完成。只运行一个实例；不要配置多个 Uvicorn worker，也不要直接开放公网访问。

如端口被占用，或希望将个人数据保存在代码目录之外：

```bash
uv run --locked tushare-collector \
  --port 7111 \
  --data-dir /absolute/path/tushare-data
```

此时访问 `http://127.0.0.1:7111/`。后续启动使用同一个 `--data-dir`，才能继续使用原有配置和仓库。新目录不会自动迁移旧数据或凭证。

### 第一次使用

1. 在“工具与设置 → 接口凭证”输入自己的 Token。默认仅本次进程有效；需要重启自动加载时，阅读明文风险提示后选择“记住 Token”。
2. 在“我的数据 → 新增数据需求”选择接口。**默认不勾选任何接口**；建议先选一个有权限的接口和较小历史范围，核对预算。
3. 点击“仅保存需求（不联网）”保存配置。保存、打开页面及查询已有仓库不会自动调用供应商。
4. 在需求详情中选择“立即同步”，核对范围并明确授权本次联网；或单独授权启用每日自动维护。
5. 在“运行记录”查看执行和错误。成功发布后，从需求详情进入“查询 / 导出”，或在“数据浏览”中切换数据。

需求会按规则准备本地股票池或交易日历等依赖，这些请求也计入预算。准备依赖不代表用户额外选择交付这些数据。每日维护只在服务运行时执行，不是安装到操作系统的后台定时任务。

> **凭证警告**：记住的 Token 保存在 `<控制目录>/.tushare-token`，是权限为 `600` 的**明文文件**。文件权限和 `.gitignore` 都不是加密。能读取文件的人、同账户恶意程序，以及备份或云同步副本均可能泄漏 Token。不要分享凭证文件或个人数据目录。

## 更新、备份与分享

更新前，先暂停自动维护和存储释放，等待当前作业结束，再正常停止服务。建议在代码目录外另存同机备份：完整控制目录，以及所有单独配置的 Raw 和导出目录；不要在 SQLite 正在写入时只复制主数据库文件。备份包含凭证时必须按敏感数据保管，也可以排除 `.tushare-token` 并在恢复后重新配置。

确认工作区无未提交修改后更新代码：

```bash
git pull --ff-only
uv sync --locked
uv run --locked tushare-collector
```

如果平时使用自定义端口或 `--data-dir`，启动时继续带上原参数。不要把“换一台机器”视为同机备份恢复：跨路径迁移需要处理原绝对路径引用，当前没有通用的一键迁移工具。保留升级前备份；旧版本程序未必能安全读取新版本修改后的数据库。

分享项目时只分享源码和必要静态资源，不附带 `data/`、`.tushare-token`、`.env`、真实 Token、个人导出或整套依赖目录。`.gitignore` 只防止通常情况下新增文件被纳入 Git，不会清除已提交历史或阻止手工打包泄密。**软件分享不等于获得 Tushare 数据再分发许可**。

## 常见问题

| 问题 | 说明 |
|---|---|
| 没有 Token 能做什么？ | 可配置和保存需求、读取已有仓库；不能向 Tushare 发起采集 |
| 选择了接口为什么仍提示权限不足？ | 适配只说明程序支持；积分、独立权限及供应商可用性以账号实际响应为准 |
| 为什么自动准备交易日历或股票列表？ | 它们用于规划日期和代码池，请求计入本轮预算；不会偷偷改用其他资产接口 |
| 为什么成功运行但没有数据？ | 成功表示请求返回符合约定，空响应不等于全市场完整或接口授权已证明 |
| 为什么更换日期或参数后需要重新确认？ | 计划冻结了范围、配置版本和来源，变更后旧确认失效，防止按过期条件执行 |
| 关闭程序后还会定时运行吗？ | 不会。已经授权且未暂停的维护会在服务恢复后按持久化状态继续推进 |
| 重启后还要输入 Token 吗？ | 仅内存使用需要重填；记住 Token 或通过启动环境提供凭证可自动加载 |
| 能否直接把服务部署到公网？ | 不建议；当前无远程多用户登录、授权和租户隔离，本地同源保护不能代替身份认证 |
| 可以删除 Raw 节省空间吗？ | 使用“我的数据 → 更多 → 存储管理”先检查再授权，不能直接清空目录 |
| 是不是完整的研究数据库或 PIT 数据？ | 不是；不保证全市场完整性，不做统一复权、财务修订合并或历史时点还原 |

## 我的数据：声明长期需求

默认首页为“**我的数据**”。数据需求与本地仓库覆盖当前股票目录的 **全部 102 个接口入口**，可按 Tushare 分类和 API 搜索选择，分类参数与接口说明按需展开。两个 `pro_bar` 入口保留独立标识；不包含其他资产类别。已有任务、归档和仓库不会自动转为需求，也不会因升级自动联网。

新增数据需求默认不勾选任何接口，至少选择一项后才能保存；修改已有需求仍保留原来的接口选择。

保存需求包含名称、数据集、各接口分类参数、历史起点、可选固定截止日、每日尝试时间（北京时间）、近期修订回查天数、请求速率及每轮请求上限。截止日留空则每轮固定为当时上海时间昨天；这是请求目标，不是供应商已发布或数据完整的证明。交易日、公告日、报告期、代码池和回查语义复用各接口预置规则，不统一当作日线。股票列表只更新执行当天的当前快照，不回放历史；仅选择快照时不设置历史截止日。停更接口首次补采历史，后续只处理已有未完成范围，不追新日期。保存时绑定各数据集及依赖的现有采集目录、当前分类参数、字段类型与采集 / 仓库规则契约，维护全部声明字段；目录、参数或契约外部变化会停止作业，须核查后重新保存。查询投影不改变长期保存契约。

**默认仅保存、不联网**。勾选启用自动维护并单独授权后，首次立即尝试，以后每日在配置时间尝试。关闭服务时不会运行；服务恢复后合并错过的时间点，不逐次补跑每个定时触发。未配置凭证时等待凭证；Token 默认仅在当前进程有效，也可单独选择本机记住。未启用定时维护的需求也可单独授权“立即同步”，不会因此开启每日调度。同一数据集只允许一个启用的维护需求。

系统在采集引擎空闲时推进持久化闭环：**递归准备依赖 → 规划差异 → 采集 → 校验发布 → 仓库查询 / 导出**。日频按需准备 SSE 市场基准日历，财务等接口准备股票列表，成员接口准备相应板块代码池；依赖去重并先于使用它的接口执行。代码池依赖须包含全部预置分类，不能用用户选取的分类子集代替。仅显式选择的接口发布仓库，隐式依赖保留供规划使用，不因此承诺历史股票池或 PIT 完整性。需求、冻结范围、分类参数、全部待执行步骤、关联运行、实际请求登记计数和发布结果均保存在 SQLite；采集运行与作业步骤在同一事务登记，防止中断后漏掉尚未开始的接口。已授权作业的中断采集在服务恢复后保留成功切片并继续，发布后未写回作业结果的中断会复用已发布快照。暂停需求会取消其排队或执行中的采集，重启不会重新启用；修改范围须先暂停，且不会自动删除范围外历史数据。

请求上限涵盖所有依赖、失败与重试，在每次请求发送前原子登记，重启不归零；发送前进程退出可能保守占用一次预算，不会为了“补足计数”额外请求。接口阶段最低请求数超过剩余预算时不启动该接口。沿用现有全局限流和最多 3 次暂错尝试，权限、触顶、预算或发布异常时停止自动执行，页面保留错误、未完成步骤及旧快照入口；核查后可重新授权同步。已有人工拆分规则的范围尚不能自动安全入仓，在该接口联网前阻止并提示核查 Raw；请求分区仓库仍拒绝相同变体下的重叠或缩窄替换，不静默丢弃历史记录。历史运行不能绕过需求暂停状态单独续跑。

托管需求的新增仓库文件在原子发布前，将读取并规范化后的源数据与 Parquet 写后回读数据做内容摘要对比，摘要记录在文件清单的 `content_sha256 / validation=normalized_write_readback`；多余未适配字段拒绝静默丢弃。本版新校验的来源同时登记 `preserved_fields` 全字段保留证明。失败不替换旧快照。此校验针对本轮写入，复用的旧来源不会被重新标记为通过全字段检查，也不证明供应商真实性、市场覆盖或回查窗口以外的修订。**中间文件默认保留**；只有单独授权存储策略后才安全释放符合条件的文件，采集规划依赖仍保留。

| 路由 | 用途 |
|---|---|
| `GET /api/data-needs/catalog` | 只读列出已支持仓库的需求能力、分类、日期语义、参数、依赖及限制，不扫描或联网 |
| `GET /api/data-needs` | 只读列出需求、目录 / 字段绑定、最近 10 轮持久化作业及步骤，不触发联网 |
| `POST /api/data-needs` | `{spec, enabled:false, authorize_network:false, expected_revision:0}`，默认仅保存；启用须显式授权 |
| `PUT /api/data-needs/{id}` | 携带当前 `expected_revision` 更新需求，执行中须先暂停；启用或修改自动维护须重新授权 |
| `POST /api/data-needs/{id}/sync` | `{expected_revision, authorize_network:true}`，创建一次完整作业；重复提交活动作业返回同一 ID |
| `POST /api/data-needs/{id}/pause` | `{expected_revision}`，关闭自动维护并暂停当前作业，不删除已采集数据 |

`spec` 的必填项为 `name / dataset_ids`；可选项为 `dataset_options`（如 `{"margin":{"exchange_id":["SSE","SZSE"]}}`，未提供的参数使用接口预置默认值）、`start_date`（默认 1990-12-19，前端历史接口要求明确日期）、`end_date`（默认 null）、`update_hour`（默认 20）、`lookback_days`（默认 7）、`requests_per_minute`（默认 100）及 `max_requests`（默认 30000）。拒绝未知、空或重复参数值；不支持单股自定义范围或自由 SQL 订阅。原有需求与执行中的旧作业兼容，无需重新创建。**本次扩展不扩大自动存储策略范围，仍仅限 `daily / daily_basic / adj_factor`，新增接口中间文件默认保留**。网络写操作沿用同源请求标识防护。页面 URL 使用 `#view=needs&need=<ID>`，刷新、前进后退只恢复导航，不代表授权。

## 存储管理：按策略释放中间文件

“**我的数据 → 更多 → 存储管理**”统一管理存储策略与全局手动释放；本地仓库页不再提供 Raw 清理或重复的存储管理入口，专注查询、更新和导出。打开窗口只读取 SQLite 策略与最近 10 轮执行记录，不扫描文件、不调用 Tushare。全局手动清理位于窗口内“手动释放中间文件（全部接口）”。

**默认关闭自动释放**，默认保留最近 **7 天**归档，使用快速检查，每日北京时间 **3 时**尝试。自动策略的保留期为 1–36500 天，按归档观察时间而非股票业务日期计算。仅保存不会删除文件；启用须单独勾选永久释放授权，修改已启用策略也须重新授权。首次启用立即尝试，以后每日在配置时间检查。服务关闭时不执行，恢复后合并错过的触发；本地释放不需要供应商 Token。

自动策略目前仅适用于 `daily / daily_basic / adj_factor` 的**当前已发布快照来源**：必须同时有来源 `preserved_fields` 全字段保留证明和对应仓库文件的写后回读校验记录，并通过现有清单、血缘、路径、共享引用、保留期、元数据及文件身份校验。其他接口、未入仓数据、旧版缺少证明的来源、未知文件和规划依赖全部保留，不把升级前的文件自动认证为可删。未被当前快照登记的重复采集副本和被替换的旧来源也暂不自动释放，不能将“本轮检查完成”理解为 Raw 已清空。重写同一月份产生的新回读记录也不会替旧来源补发全字段证明。

沿用现有单进程采集协调器，在采集与需求作业空闲时分批推进，每批最多检查 100 个来源。SQLite 持久化策略版本、目录 / 字段绑定、冻结参数、扫描游标和精确批次指纹；完成的批次也保留指纹回执，连接策略版本与已有逐文件清理审计，状态接口只返回批次数以避免反复传输整份审计。先保存批次，再登记删除意图，再按现有安全规则逐文件释放。确认及删除事务均检查授权仍有效。批次之间优先运行采集；有排队采集或发布锁占用时等待，不视为释放失败。暂停在当前小批次结束后阻止后续释放，重启不会重新启用；仍获授权的执行中批次可恢复，不扩大原范围，也不自动接管此前的手动或已失败清理。

目录、字段契约或执行中快照变化，以及元数据损坏、权限、删除或发布证据异常会停止后续批次并保留错误，不自动循环重试。已完成部分不会回滚；核查后可重新保存授权，已登记的未完成旧批次可在全局手动预览后明确确认重试。原始响应不能完整重建，快速模式仍不能发现所有内容损坏；深度模式重新计算数据文件哈希，耗时可能较长。策略不删除仓库快照、导出副本、数据需求、未登记文件或目录，也不递归清空 Raw。

| 路由 | 用途 |
|---|---|
| `GET /api/storage-policy` | 只读取得策略、绑定、安全范围及最近执行记录；未保存时返回关闭状态，不创建策略或扫描文件 |
| `PUT /api/storage-policy` | `{retention_days, update_hour, check_mode, enabled:false, authorize_delete:false, expected_revision:0}`；首次版本为 0，后续须携带当前版本；启用必须显式授权，执行中须先暂停 |

## 预置数据集：按目的开始

“高级工具 → 预置采集”展示统计与数据集目录，默认紧凑列表，也可切换卡片；默认首页为“我的数据”。保留执行结果和实际可确认的记录日期，不提供“当前关注与待处理”区块或完整性状态展示。记录截至日期只使用已发布请求分区中的实际记录日期，或所有已检查日期均有记录的日期型快照；其他情况明确未知。移除完整性展示不改变后台文件哈希、字段、来源、触顶及入仓校验，也不将已有数据标记为完整。当前尚无统一的接口发布时间证据，**不按今天日期推断更新是否到期或历史缺口**。

“已有预置采集归档”“存在本地原始文件”“支持标准仓库”和“已发布可查询快照”是不同口径。数据集概览串联采集、请求台账、仓库查询/字段导出、Raw 追溯与运行记录。运行成功 0 行显示“请求成功 · 无数据”；恢复入口优先使用结构化权限、额度及触顶原因。明确的接口名错误转配置，已知网络暂错可重试未完成部分；未分类错误必须先核查并确认，不默认当作网络问题。

主页面、数据集和主要筛选保存在 URL `#view=...` 中，支持刷新恢复、前进后退与收藏。数据集使用 `dataset`，原始归档入口使用 `entry/run/slice`；各视图筛选使用独立前缀，未知或非法入口参数会忽略并提示。URL 不保存 Token，也不能启动采集或恢复待确认的写操作。仓库已有快照时优先查询，联网采集与离线整理仍需分别确认。

预置采集页提供“查询一次 / 首次采集 / 更新数据”。每个数据集展示“未采集 / 采集中 / 最近完成 / 需要处理”，只突出一个当前动作；覆盖、补采、拆分、组合勾选和技术详情位于卡片“更多”。自定义 API 位于高级工具，组合管理默认收起。状态仅依据当前目录与规则的执行记录，不表示全量覆盖。

选择数据时按 **股票数据 → Tushare 分类 → 具体数据** 逐层选择，分类名称及顺序直接读取已有股票目录。桌面左侧分类导航，右侧展示该分类的数据集；手机使用分类下拉框。股票目录的 **102 个入口均有明确的全量 / 更新规则**，涵盖八个分类；实时、当前成员和已停更数据会标明能力边界，不冒充可回放的历史接口。分类数字表示当前目的下可采集 / 更新的数据集数与目录接口数。切换分类不会发送供应商请求，也不会清空跨分类勾选的组合成员。

### 查询一次

“查询一次”先选择分类，再选择该分类下的具体数据；卡片“更多 → 查询一次”会预选对应分类和接口。每个分类记住本页面内上次选择的接口，各接口分别保留输入条件。支持参数表单、高级 JSON、返回字段选择和 Raw 保存目录。先点击“检查请求”，后端验证 API、条件和字段，但不创建运行或请求供应商；核对摘要后点击“确认查询并查看结果”。修改条件、字段、目录或切换分类 / 接口会使确认失效，必须重新检查。示例股票和日期可修改。SDK 派生 `pro_bar` 可能产生多次内部请求，故不在此入口提供，仍可使用高级 API 采集。

确认后只创建一个串行 SDK 查询，沿用全局限流，最多尝试一次，不自动重试、分页或扩大范围。查询可能返回很多行，并非在供应商端只取预览页；请先限制股票和日期范围。空响应明确显示为空，不能据此推断休市或账号拥有权限。触及目录行数上限仍标记为疑似截断失败，已有可读表格仍可预览。

查询结果按现有规则归档为 Parquet，完成后直接打开表格，支持本地分页、字段类型、实际参数、哈希校验及导出；翻页不会重新请求 Tushare。各接口的参数表单、未完成 JSON、字段选择和保存目录在本次页面内分别保留，切换接口或关闭再打开不会重置；页面刷新后需重新填写，不持久化查询草稿。关闭查询窗口不会取消已经入队的请求，执行详情可手动取消。完整记录保存在运行历史中，刷新或重启后保留。查询配置不加入可复用任务列表，预览不依赖本地日历或股票池，不修改任何数据集设置或全量/增量覆盖台账。缺少 Token 或执行线程时不能提交查询。

## 本地数据阅读器

本地导航使用独立的研究语义分类：**标的与交易基准、量价与复权、财报与业绩、股东治理与股本、资金流与北向、两融与转融通、行业板块与成员、交易事件与市场情绪、研究信号与机构观点**。102 个接口入口分别归类，两个 `pro_bar` 入口保留各自标识。分类只帮助定位原始归档，不创建合并业务表或改变采集规则。

`GET /api/local-data/navigation` 提供业务域、接口和已登记归档摘要。支持 `raw_root`、接口名称/API/官方分类关键词 `q`、`business_domain` 和 `include_empty`（默认 `false`，只返回本地有文件登记的接口）。业务域统计受目录和关键词筛选影响，不受选中业务域或空接口显示开关影响；顶层摘要受选中业务域影响。`include_empty=true` 可浏览全部定义，未采集接口明确显示无归档。目录选择项始终返回全部已登记 Raw 根目录。

摘要明确标记 `summary_basis=registered_archives`、`hash_verified=false`、`coverage_verified=false`：文件数和成功行数来自 SQLite 登记，包含重复采集；失败归档单独计数，不算成功行数。最近采集时间是有归档的运行最近结束时间，不是数据的业务日期或最新有效版本。导航不扫描文件、不推断真实股票/日期覆盖，缺失或损坏文件仍保留登记，打开时明确报错；已删除或正在清理的归档不计入摘要。

`GET /api/local-data` 保留原有参数和分页，增加 `business_domain` 与 `source_type=dataset|preview|task` 筛选，每条归档返回业务域和来源。来源依次判定单次查询、预置数据集、其他任务；选接口后仍阅读单个原始归档，不跨文件查询、去重或自动选“最新版本”。

“**高级工具 → 原始归档**”可直接查阅当前 SQLite 已登记的 Raw 归档，不需要 Token，也不会调用 Tushare。包括数据集采集、单次查询、高级任务及有文件的失败切片；不受最近 100 次运行列表限制。可按 Tushare 分类、具体接口、Raw 目录、切片状态筛选，按任务名称、股票 / 日期请求条件或运行 ID 查找并分页浏览。列表依据登记记录，不会把文件缺失自动当作零条数据；打开文件时检查路径、元数据与 SHA256，失败会明确提示。

点击“阅读数据”后显示字段类型、实际参数、归档时间、原切片状态和分页表格。可按全部字段或指定字段搜索实际数据行，使用不区分大小写的字面包含匹配；不执行 SQL、正则或 Python 表达式。搜索跨当前文件所有行，匹配结果独立分页；Parquet 分批扫描，JSON 保留已有 64 MiB 读取上限。选择显示字段仅影响表格，不改文件。切换文件重置搜索与显示字段，同一文件翻页保留条件。导出仍是完整原始切片，**不受搜索、显示字段或当前页限制**。

此入口不扫描任意文件目录、不导入外部 Parquet、不跨批次合并、不去重，也不补记覆盖台账。正常阅读为只读操作。列表统计中的行数只汇总尚未删除的成功切片登记值，可能包含重复批次；失败归档的实际行数在打开表格后显示，不能据此推断完整性。

**请求分区仓库**（`storage_layout=request_partitions`）：每个原始请求分区写一个规范化 Parquet，最新成功响应整体替换同一分区，成功空响应也可替换旧记录。不按股票、公告日或报告期去重，财报不同 `report_type / comp_type / update_flag` 及重复原记录全部保留。查询按目录日期列过滤：三张财务报表按 `ann_date`，财务指标按 `end_date`，交易日历按 `cal_date`；成员查询的代码列是 `con_code`，不是板块 `ts_code`。状态中的 `partitions` 是请求单元数，`days/days_with_rows` 是实际返回记录的不同日期数（`date_count_kind=record_dates_not_coverage`），不是已检查日期数，也不表示请求日期范围完整。

请求中的类型、市场、频度等形成独立变体，股票代码和切片日期不构成变体。状态提供 `variants`，有多个变体时，读取与导出必须指定属于该快照的 `variant_id`；只有一个时可自动选择。不同变体绝不隐式混表。参数选项配置也纳入仓库目录标识，修改选项使用独立仓库。同一实体及选项的不同分区若日期重叠，或同一分区的新请求范围收窄，拒绝发布，保留旧快照；已有父子拆分规则的范围暂不发布请求仓库，仍可读取已发布版本。需要先补采原完整范围，不能用去重或局部覆盖掩盖冲突。

新补齐的 21 项使用**记录型请求分区引擎**，保留重复原记录，并通过 `date_semantics / atomic_full_run / semantic_note` 显示各自规则：

- 当前资料、分类、关系及实时接口仅发布同一次完整成功运行的全部计划切片，删除的旧记录不继续累积。实时采集记录 `capture_window`，是一轮逐股采集，不是同一时刻的行情快照或持续订阅；不接受历史日期筛选，不混用参数变体。
- `stk_mins` 的 `trade_time`、`report_rc` 的 `create_time`、`stk_nineturn` 的日内日期原值保留；日期筛选按上海自然日。声明为时间类型的字段保存为纳秒精度时间戳，未约定的时区明确拒绝，不静默移除。
- 券商金股按 `YYYYMM` 整月区间相交筛选；旧开户统计保留 `20141229~0102` 等跨年周区间，按原区间相交筛选。周/月线保留原周期标签，不展开为日线。周期数不等于完整覆盖天数。旧接口仍可能被供应商拒绝，不换用其他接口冒充旧口径。
- 复权因子类历史、复权周/月线与两个 `pro_bar` 入口按完整运行整段替换；需求每轮全量规划，不将局部增量与旧运行拼接。新历史范围不能缩窄已发布范围。人工局部成功运行会明确提示未发布，旧快照仍可查询。`pro_bar` 仅保存官方 SDK 的固定股票行情字段，不将日线接口非默认返回的盘后字段当作 SDK 必返字段；需求不启用自定义均线或附加因子。
- `stk_surv.content / hm_list.orgs` 按可逆 JSON 文本保存，清单 `field_encodings` 标明编码；结构化值与大整数不静默丢弃。其他未适配字段、类型及写后回读差异仍拒绝发布，保留 Raw 和旧快照。

每个仓库只纳入该数据集当前配置 Raw 目录、同范围标识下的预置成功归档，不自动导入自定义任务、即时查询或外部文件。日频按 `trade_date` 归集：每个日期选最新成功归档，内容哈希相同则复用现有数据；失败重采不替换已发布数据。整理时核验数据 / 元数据 SHA256、接口身份、来源与日期，要求适配器定义的全部字段，并验证每个日期股票代码业务键不重复。缺字段、损坏源或日频重复业务键明确失败，不能用空列补齐或静默丢弃重复行。

日期语义由目录 `date_column / calendar_basis` 声明，不一律等同交易日：`pledge_stat` 按统计截止日 `end_date`，`st` 按公布日 `pub_date`，`stk_alert` 按生效起始日 `start_date`；查询和导出的通用 `start_date/end_date` 是针对该日期列的过滤区间。`weekly/monthly` 逐开市日检查周/月线，非周期结束日允许为空，不猜测未结束周期；`days` 表示已检查日期数，`days_with_rows` 才表示有记录的日期数。空请求日计数不证明市场完整，Bundle 的 `days` 只统计实际导出记录中的不同日期。

`date_records` 明细（例如大宗交易、机构龙虎榜）与 `board_records` 板块数据原样保留多行及重复行，导出强制保留目录中的定位字段，但不宣称它们唯一，也不做跨记录合并。板块查询沿用 API 的 `ts_code/ts_codes` 参数名，允许 1 至 32 位字母、数字、点、下划线和连字符（例如 `885001.TI`），不强制股票后缀。市场汇总 `aggregate_series` 没有 `ts_code`，只按日期、字段筛选；传入股票或板块筛选会明确拒绝，导出只保留日期定位字段，不添加伪股票列。

**当前快照试点 `stock_basic`**：只选择同一个最新完整成功运行的 15 个交易所 × 上市状态切片，允许无对应状态股票的空切片；不混合局部成功运行。整体股票代码必须唯一。每次发布一个按 `ts_code` 排序的 `current.parquet`，新完整快照替换当前表，不把不同时点股票列表追加到一起。读取及导出可按股票、字段筛选，必须保留 `ts_code`；不接受起止日期筛选，也不把 `list_date` 冒充历史股票池。状态使用 `partitions / available_source_partitions` 计数，`days=0`、`first_date/last_date=null`；`months` 兼容字段内的 `month=current` 表示快照文件而非月份。固定旧 `snapshot_id` 是不可变文件引用，不代表 PIT 或指定历史时点股票池。

**公告事件试点 `dividend`**：按照自然日 `ann_date` 归集、过滤和分月存储，不依赖开市日、不按报告期 `end_date` 过滤。一个股票一天可以有多条分红方案、进度或重复原记录，全部保留，不去重、不做跨公告日方案追踪。每个公告日重采后替换该日完整返回记录，而非逐行拼接；成功空响应可记录为已检查自然日，但不能证明供应商公告完整。导出始终保留 `ts_code / ann_date / end_date / div_proc` 作为定位字段，这四列不宣称唯一主键。`days` 包含已纳入的成功空公告日；Bundle 的 `days` 仅统计筛选后有记录的公告日。旧公告的实施进度修订需要主动扩大回查窗口。

股票快照与分红公告会原样保留供应商历史上海股票标识（`T` 加五至六位数字及 `.SH`，例如 `T600018.SH`、`T00018.SH`），查询与导出筛选同样支持。不会猜测或改写成现代代码，也不会把不同标识自动关联为同一股票。其他日频仓库仍沿用六位数字及 `.SH / .SZ / .BJ` 的校验范围。

仓库保存在 `<控制目录>/warehouse/<dataset_id>/<repository_id>/`，数据集和不同 Raw 目录使用独立仓库。日线仍使用原 Raw 目录 SHA256 标识，其已有文件不迁移或重写。`current.json` 原子指向 SQLite 已登记的不可变 `snapshots/<ID>/manifest.json`。清单记录实际日期、源归档、数据哈希和适配器字段类型。日期型按月存储并排序；请求型按原请求键的 SHA256 存储在 `partitions/`，保留分区内源记录顺序，跨文件分页顺序固定但不保证全局日期排序。变动分区重写，未变动分区引用已有不可变文件。适配器明确使用 Float64 / Int64 / string / timestamp[ns]，不把整数成交量或状态字段统一转为浮点数，非整数值无法安全转 Int64 时明确拒绝。大于 JavaScript 安全整数的读取值转为精确文本，Parquet 本身保留 Int64。仓库不二次计算复权价格或其他指标，Raw 仍保留原始类型及精度证据。单个规范化文件内存处理上限为 100 万行，超限明确拒绝发布，不截断。

日常默认读取当前快照。翻页和导出可固定 `snapshot_id`，避免同步期间混读；导出包还保存源快照清单及其指纹。非整段发布接口的相同内容新归档只推进内部同步游标；记录型完整运行则发布新快照，即使记录相同也保留本轮来源与采集时间窗。删除 Raw 不删除已发布仓库副本或 Bundle，也不会因只剩旧 Raw 而自动回退当前数据版本；清理仓库副本尚无自动入口。历史文件保留用于固定引用，不提供 PIT、任意历史回放或历史版本清理功能。

可直接读取仓库文件：先一次性读取 `current.json` 的 `snapshot_id`，再读取该快照清单，根据兼容字段 `months[].file` 相对仓库根目录定位文件。请求型的 `months[].month` 是请求键哈希，`label` 才是原始请求键，`kind=request_partition`，不能按月份解释。**不要扫描全部 snapshots 或拼接所有历史文件**，否则会重复读取修订版本。文件路径可能属于较早快照，必须以当前清单为准。多变体直读还必须按清单中的 `variant_id` 选择对应文件。状态中的起止日期、日期数和行数是已发布实际数据摘要，不证明整个市场或请求范围完整。

`dataset_id` 允许上述 102 个适配项；未知项返回明确错误，不回退到日线。数据快照、查询和导出按数据集隔离，不能把日线快照 ID 用于其他仓库。结果包含 `dataset_id / entry_id / name`，原日线路由及旧快照兼容。请求型及记录型结果与导出清单另记录选定的 `variant_id`；其他引擎显式拒绝变体参数。

导出默认所选数据集全部字段；选择部分字段时仍保留目录声明的定位字段（日频为 `ts_code / trade_date`）。显式投影最多 500 列，支持 `stk_seasoned` 等超过 50 列的完整字段子集；`columns=[]` 始终表示全部已声明字段。每次生成独立的 `<导出根目录>/tushare_warehouse_bundles/<dataset_id>-<ID>/`，包含筛选和字段投影后的 Parquet、`manifest.json` 和 `source_snapshot.json`。不同日期范围或指标选择可以各自导出，不需要逐个勾选数千切片，不修改仓库或 Raw。空范围、无效字段或损坏文件明确报错，不发布半成品。

**文件组织与排序**：`file_layout=partitioned`（默认）且 `sort_by=[]` 时保留原分区；`file_layout=single` 合并为唯一的 `data/data.parquet`，可包含多个 row group。`sort_by=[{"column":"ts_code","direction":"asc"},{"column":"trade_date","direction":"desc"}]` 最多 10 项，字段必须在导出字段中且不能重复，方向为 `asc/desc`。排序按字段实际类型执行，空值放最后，不去重；相同排序键的行不承诺原始相对顺序。多文件排序是全局排序，输出 `part-000000.parquet` 等连续行范围分片（每份约 100 万行），不再代表月份或原请求分区。消费者须按清单 `file_order` 读取，不依赖目录扫描顺序。清单保存文件组织、排序、源文件哈希和源快照信息。重组过程用 DuckDB 的 256 MiB 内存预算与临时磁盘排序，再分批写 Parquet；请预留筛选结果及排序所需的临时磁盘空间。失败不发布半成品。

**按维度拆分**：前端选择“按字段值拆分（每值一份）”，再选择已勾选的导出字段；API 使用 `file_layout=grouped` 和 `split_by="ts_code"`（例如每只股票一份）或 `split_by="trade_date"`（每个交易日一份）。按字段的实际值分组，跨月、跨请求源文件的同值记录合并到同一份，空值单独一组，保留重复行，不按百万行再次拆分。日期字段按原值拆分，不自动转换为年/月。每次最多 10,000 组，超限明确报错且不发布 Bundle；高基数字段请缩小范围后再导出。分组按拆分字段升序排列，若 `sort_by` 包含拆分字段则采用其方向，空值始终最后；其余排序字段仅在各组内生效，不承诺其他字段跨文件全局有序。结果使用安全序号文件名 `data/group-000000.parquet` 等，清单 `split_by`、`files[].split_value`、`file_order` 记录字段、各文件对应值和读取顺序，`sort_scope=within_group`；大整数拆分值在清单中保存为精确字符串，Parquet 保留原类型。非 `grouped` 模式不可传 `split_by`。原分区、单文件模式及默认行为不变，不修改仓库或 Raw。

共享引擎负责校验、原子发布、文件复用、固定快照读取和导出；显式适配器负责接口身份、字段类型与数据形态。当前包括 `date_cross_section / current_snapshot / announcement_event / period_bar / date_records / board_records / aggregate_series / financial_records / calendar_records / partition_records / temporal_records`，不做财报合并、事件多行去重、分钟频度转换、跨接口关联或完整 Tushare 副本保证。

#### 删除本地归档

手动释放统一位于“**我的数据 → 存储管理**”：先检查当前已发布快照及源切片对应关系，再显示预计切片数、文件数、释放空间及文件清单，必须勾选确认后执行。可保留最近 0–36500 天归档，按归档时间而非业务日期计算，0 表示不额外保留。未进入当前快照的更新、未适配数据和未知文件不在清理范围内。证券列表 `stock_basic` 和交易日历 `trade_cal` 是后续采集依赖，本版暂不允许此类清理。原有单接口清理 API 保持兼容，历史未完成批次仍可通过全局手动检查明确确认后重试。

**默认快速检查 `check_mode=fast`**：仍验证仓库清单哈希、来源登记、精确路径、共享引用、保留期与仓库 Parquet 页脚的行数及字段；预览只检查 Raw 文件属性，不读取其内容，不重算 Raw 或仓库数据文件 SHA256。确认时重新检查范围，并读取、核验、保存原始元数据；删除前再次核对设备、文件身份、大小及修改时间，变化则拒绝继续。目录检查只在单次预览中复用，确认及重试不复用旧的路径检查。候选数量较大时仍须遍历文件，并非即时查询。快速模式能发现预览后文件身份或属性的变化，**不能保证发现入仓后至预览前的内容损坏，也不证明入仓业务内容正确**。可手动选择 `deep` 深度检查，重新计算 Raw 与仓库数据文件哈希，耗时更长；普通“删除归档”仍保持原有严格哈希检查。

“**存储管理 → 手动释放中间文件（全部接口）**”可一次检查所有已适配接口，不需要逐一选择数据集。统一设置保留天数和检查模式后，展示各接口切片数、文件数、预计释放空间和跳过原因，再勾选并确认全局执行。修改保留天数或检查模式会使页面已有确认失效。清理范围或快照在确认前有变化，整次确认失效且不会开始删除；执行期间逐接口重新核验，已完成部分不会因其他接口失败而回滚，结果明确列出失败项。重新全局检查可同时确认并重试之前持久化的未完成清理；对旧确认的重试仍沿用其原始快照、保留期与检查模式，不会把历史深度检查降级为快速检查。页面加载和切换数据集不会自动扫描或清理；服务中断时，尚未登记清理意图的接口须重新检查确认，不能把“无待重试记录”视为全局已完成。手动释放保留原有明确确认的字段丢失风险，不会因自动策略的更严格门槛而取消旧功能。

“已入仓清理”与下方普通删除不同：SQLite 保留入仓血缘和清理记录，已入仓切片不因 Raw 清理自动成为采集缺口，但不再作为可读取的 Raw 依赖。现有仓库查询和导出不依赖这些源文件。**该操作仍不可撤销且不是无损归档**：仓库只保留已适配字段，删除后不能保证重建原始响应、补取其他字段或离线重新适配；需要时应先自行备份。采集或整理期间拒绝执行，确认时范围有变化须重新检查；只删除确认的文件，不递归清空目录。

列表“**删除归档**”和阅读窗口“**删除当前归档**”会先校验并列出当前切片的数据文件、元数据文件、完整路径及字节数，再要求单独确认。确认后**永久删除这两个已登记文件，不可撤销**；搜索、分页和显示字段不会缩小删除范围。不删除其他切片、其他批次、旧尝试、导出副本或未知文件，也不删除采集配置、运行历史和尝试记录。文件身份、哈希、引用关系或路径不一致时拒绝删除；有任何排队或执行中的采集时也拒绝删除，避免破坏正在使用的依赖。

删除意图先持久化到 SQLite。该份归档随即退出本地列表和可用覆盖，不能再预览或导出；数据集增量会重新检查并补采，已检查但未启动的计划会失效。同范围还有其他成功归档时，保留其可用覆盖。运行中的“采集成功”是历史结果，详情会另行提示归档已删除，不伪造为采集失败；含删除归档的旧失败运行不能直接续跑，应重新检查计划。

如果权限或服务中断导致文件只删除了一部分，不显示为删除完成。本地数据页会保留“尚未全部清理”的提示和“重试清理文件”入口；重启后仍可继续清理，仅处理原先确认的文件。已清理文件不会重复要求存在，文件内容或路径发生变化时仍拒绝继续删除。空目录可以保留，不递归清理目录。

## 配置、凭证与运行限制

打开 **http://127.0.0.1:7110/**。通过“工具与设置”或侧栏底部配置 Token，默认仅在当前进程使用。勾选“**记住 Token**”并保存后，服务启动会自动读取 `<控制目录>/.tushare-token`（默认 `data/.tushare-token`），无需再次输入，也不依赖上一级 `token` 文件。启动前设置的非空 `TUSHARE_TOKEN` 环境变量优先于本地文件；界面更新凭证则立即应用于当前进程。

本地文件是**明文而非加密存储**，以仅当前用户读写的 `600` 权限原子写入，不放入 SQLite、浏览器存储或任务配置。启动拒绝权限开放、符号链接及损坏的凭证文件，并明确报错，不静默忽略。状态 API 只返回是否已配置、是否已保存和文件路径，永不返回 Token。凭证及临时文件已加入 `.gitignore`，但忽略规则不是加密，也不会排除已提交文件；分享、备份或上传时不要附带凭证文件或整个个人数据目录。

**风险提示**：任何能读取该文件的人或程序都能直接获得 Token，包括同一账户下的恶意程序、管理员，以及获得备份或云同步副本的人。程序在凭证设置中醒目展示此风险，“记住 Token”明确提示接受明文风险；侧栏、工具菜单及保存提示均标注“明文”。有顾虑时只在当前进程使用，不选择记住。

不勾选“记住 Token”而提交新凭证，会删除之前保存的本地凭证，仅本次进程有效。“清除本机凭证”同时删除本地文件并清空当前进程凭证，不删除数据，不撤回已发出的请求。如果启动环境仍配置 `TUSHARE_TOKEN`，重启仍会加载该变量；要彻底停用须同时移除该环境变量。更换 `--data-dir` 使用独立凭证，不自动复制其他目录的 Token。

| 路由 | 用途 |
|---|---|
| `PUT /api/credential` | `{token, remember:false}`，默认仅内存；`remember:true` 明确授权本机明文保存，写入失败不切换当前凭证 |
| `DELETE /api/credential` | 清除本机文件及当前进程凭证；与保存接口一样要求同源请求标识 |

可选参数：

```bash
uv run --locked tushare-collector --port 7111 --data-dir /absolute/path/collector-control
```

`--data-dir` 或 `TC_DATA_DIR` 设置本项目的 SQLite 控制目录；默认 `tushare_collector/data`。`TUSHARE_GLOBAL_RPM` 设置全局请求频率上限，默认 500，取值 1–500。新任务与新数据集的默认任务上限为 500；已保存的配置和设置不自动修改。实际频率取全局、任务配置和接口审核限流中的最小值；SDK `pro_bar` 的每个实际子接口也分别限流。

### 8000 积分权限与接口限流

已逐项审核股票目录 102 个入口的官方文档及[积分频次总表](https://tushare.pro/document/1?doc_id=290)。审核结果保存在 `src/collector/permissions.json`：每项包含官方链接、审核时间对应的文档哈希、最低积分、独立授权名称、8000 档频率、日额度、来源和冲突说明。`GET /api/permissions` 提供完整清单；目录和采集设置页展示对应权限说明及文档链接。积分是用户声明，不读取账号积分、不表示已经验证实际授权。

| 接口 / 类型 | 8000 积分下本地限流 |
| --- | --- |
| 常规积分接口 | 总表 500 次/分钟，接口页有更低限制时取更低值 |
| `stock_basic`、独立授权的 `rt_k` | 50 次/分钟 |
| `ths_member`、`cyq_chips` | 200 次/分钟 |
| `stk_factor`、`stk_factor_pro`、涨跌停及连板等明确 8000 档接口 | 500 次/分钟 |
| 未公布 8000 档频率的接口 | 标记未知，本地保守 30 次/分钟，不宣称这是官方限额 |
| `hm_detail` | 要求 10000 积分；当前会在发送请求前明确拒绝 |

`report_rc` 为每天 100000 次；`cyq_perf` / `cyq_chips` 为每天 20000 次；历史分钟 `stk_mins` 为滚动 24 小时 300000 次。为避免官方未明确自然日时区，本地对这四类均采用更保守的滚动 24 小时计数。请求额度先持久化至 SQLite `api_requests`，包含重试和失败请求，重启不清零；触顶明确失败，不自动跨日等待或继续发送。只保留最近 24 小时的请求计数证据；同接口最小请求间隔也跨任务、跨重启共享。其他程序或独立采集器使用同 Token 的请求无法计入此处。

盘前股本、实时日线、历史分钟、两种实时分钟、三种集合竞价共 8 个目录入口需独立授权，8000 积分不包含它们。仍允许用户明确提交已开通的接口，但不自动认定授权存在，供应商拒绝时照常报错。`namechange` / `hsgt_top10` 门槛未公布，不伪装成免费。部分接口页与总表存在差异（盈利预测、券商金股、限售解禁、龙虎榜机构等），每项保留冲突说明，采用明确的接口档位或较高门槛；未公布的 8000 档特色频率不套用 10000 档的 300 次。

只监听 `127.0.0.1`，只支持一个服务进程。不要用多个 Uvicorn worker、复制进程或把控制台暴露到公网。本地同源请求保护不是远程多用户认证。

### 多采集线程

单个服务进程使用一个协调线程领取运行，再由 **1–16 个采集线程**并发执行当前运行内的已确认切片。默认 1。线程数通过 `GET /api/worker/settings` 查看，通过 `PUT /api/worker/settings` 提交严格整数 `{"collection_threads": 4}`，写请求沿用 `x-collector-request: 1` 保护。设置保存到 SQLite，重启保留，无需重启即可修改。修改只影响下一个运行：当前任务使用启动时的线程数，不临时扩大或缩小已经确认的执行并发。

不同运行仍按队列执行，依赖任务完成后才开始后续运行；不是多个 Uvicorn 进程并行抢任务。同一运行有多个切片时可以重叠网络请求、校验和归档。单次查询只有一个切片，不会复制请求。每个切片独立使用客户端和归档目录，重试等待期间保留切片执行权，不能被其他线程再次领取。

所有采集线程共用原子请求准入。全局、当前运行和实际 API 的最小请求间隔检查，以及滚动 24 小时额度登记在同一 SQLite 事务中完成；等候期间不占用写事务，重新检查后才允许发送。SDK 派生子请求也走该入口。线程数不会扩大供应商额度，当前请求队列不保证线程间公平。

取消、服务关闭或普通失败会停止派发后续请求和重试，但已经发出的请求须完成响应及归档后才结束运行；不会中途杀线程或丢弃可保存的响应。结果保留已经完成的成功切片，未执行范围仍可重新检查或续跑。支持拆分的行数触顶沿用原规则，继续其余已确认切片，不自动扩大请求范围。`/api/activity` 保留单个 `active_run` / `current_slice` 兼容字段，同时提供 `active_runs`、`current_slices`、线程列表、忙碌数以及配置/当前实际线程数。

检查会显示实际归档单元、供应商子请求数、所选类型及估算耗时。仍保留单次 20,000 个请求切片上限，超限显示所需数量并拒绝创建部分运行；需缩小历史范围或分开选择频度/类型。未知上限使用明确的本地保守阈值，达到阈值即失败，不推定已取完；仅在供应商支持筛选的维度上生成新的确认拆分计划。无股票筛选的单日回购、字典和单股单日等无法安全细分的请求会停止，不假造分页。实时权限、账号积分、早期数据缺失及空响应仍可能限制实际可取得的数据；预置规则不代表已完成真实全量采集或数据完整性审计。

1. 点击“首次采集”，选择所需数据集。未配置的非快照数据集不预填几十年历史，必须手动选择起点，也可明确选择近一年或近三个月。选择截止日期和保存目录后检查依赖与计划；频率、回查和策略在“更多设置”中。
2. 缺交易日历、股票列表或板块分类时，检查页直接说明原因、依赖范围和请求数。存在多层依赖时先准备当前缺少的底层依赖。确认只准备该依赖；成功后自动恢复原表单、选项并重新检查，**不会自动启动原采集**。再次核对原数据范围和请求数后，分别确认启动。
3. 后续点击“更新数据 / 检查更新”。先看到最近结果和未完成数量，再检查从已配置历史起点到截止日的新日期、缺口、失败范围及近期回查，展示请求量和限流耗时估算。回查窗口默认为 7 个自然日。沪深北日频沿用 SSE 市场基准日历，不判断个股停牌。
4. “补采未完成”只选择此前已计划但未成功的分区，不额外扩展新日期。也可在结果中按原固定配置续跑。数据集设置不改变旧运行。

历史请求的截止日最多为**上海时间昨天**，保守采用 D+1。当前快照及明确标注的实时接口不受历史日期筛选，不表示能回放过去。原有日频行情的全市场开市日空响应会失败；新增事件、周/月周期空日及个股未上市/停牌日期按具体接口规则允许为空，不能据此推断历史完整或账号有权限。股票列表中非上市状态可以为空，上市状态为空则失败。

财务与分红也只计划到上海时间昨天。财务股票池读取并校验股票列表 SSE/SZSE/BSE × L/D/P 九个成功归档，包括退市股票，不包含 G/UN；与本目录已登记的历史财务股票代码取并集，避免股票池变化后遗漏已有失败分区。股票池缺失或归档损坏时需先重新采集股票列表，不请求 VIP 接口，不凭在线接口自动补齐。该快照不证明历史股票池完整或 PIT。报告和公告允许空区间、多报告类型及重复股票代码，不合并修订。财务段以 1990 年为锚点划分，边界随所选范围裁剪；扩大起止范围时会重新采集此前成功范围未包含的部分。财务指标采用文档 100 行阈值；另三张财务表因目录未给出明确上限，采用保守的 100 行检查阈值，触顶须进一步拆分。分红只发送接口支持的 `ann_date`，不构造无效的 `start_date/end_date`。

“检查采集计划”只持久化本次确认计划，不修改长期数据集设置，也不请求 Tushare。仅“保存设置”或“确认启动”会保存所选设置；关闭未启动的计划后，重新打开仍使用原长期设置。启动时使用计划中冻结的范围，并检查长期设置的基础修订号没有变化；保存设置与创建运行在同一事务内完成。组合检查及依赖阶段对日历起点的临时扩展同样不会提前保存，实际确认执行的非空成员才保存设置。

日频检查只读取已归档且通过哈希和完整日期检查的日历。依赖检查计划不保存原任务或依赖长期设置。确认依赖后，将原策略、日期和目录与实际依赖运行关联；成功后自动返回并重新检查原计划，依赖失败则保留结果与恢复入口。其他数据窗口打开时延后返回，避免遮住正在查看的内容。返回记录按本地数据库隔离，保存在浏览器草稿中，刷新后仍可恢复并重新检查；不恢复可直接启动的旧计划。仍可在“更多设置”手动准备依赖，或从依赖弹窗、结果和首页主动返回。浏览器存储不可用时明确提示仅在本次页面保留。日历最近更新失败时，若有完整旧成功快照，允许重新检查并明确确认使用旧快照。

预置交易日历及日频依赖统一使用 **SSE 上交所市场基准**，依据 [Tushare 日历文档](https://tushare.pro/document/2?doc_id=26)对三大交易所日历相同的说明；计划明确展示来源，不复制 SSE 为 SZSE、不根据缺失返回推断休市。早期 SZSE 空响应不再阻断默认市场日历。旧双所运行的真实 SSE 成功归档在同目录与原范围中继续复用并严格核验，SZSE 历史归档和失败记录保留，但不计入当前基准覆盖。请重新检查“更新数据 / 补采未完成”；包含非 SSE 未完成切片的旧预置日历运行拒绝直接续跑。旧确认计划按新规则重新校验，变化后必须重新确认。需要 SZSE 原始日历时仍可通过“查询一次”或高级 API 明确查询，结果不自动作为预置市场日历依赖。

计划持久化到 SQLite，有效期 30 分钟。启动在同一事务内重新检查设置版本、覆盖台账、依赖日历、接口字段和预置规则；变化后拒绝旧计划。同一数据集不能创建多个并发运行，但当前运行内可使用配置的采集线程并发切片。重复提交同一计划不会创建第二次运行。没有待采集切片时不创建空运行。预置运行沿用运行队列、共享限流、重试、取消、归档、预览及导出。

覆盖台账记录每个请求分区及其对应切片，重启后保留。失败的近期回查不会抹去以前成功的归档，但会标记未完成并再次补采。更换 Raw 目录或规则版本后使用独立覆盖范围；改变历史起点或回查窗口可复用同目录内已经登记的分区。现有自定义 API 运行不会自动导入预置台账，不能凭其最大日期假设已完整初始化。

数据集卡片的“覆盖台账”可按日期、年度、交易所/状态查找并分页查看已计划分区，分别展示最近执行状态和最近成功归档。更新失败时仍可预览此前成功的数据；从未计划过的缺口在增量计划中生成，不会在台账中伪装成已覆盖。

结果页显示成功、失败、未执行数量及具体请求条件，各状态可搜索、翻页查看全部范围，不限前 500 个。提供“查看数据 / 处理失败 / 再次更新”。普通失败可按原固定配置续跑；包含触顶失败时不提供直接续跑按钮，必须重新检查拆分方案并确认，不自动扩大请求。定时同步仅展示尚未提供的说明和禁用入口，当前不会自动定时执行。

**台账中的成功分区只是执行记录，不是完整性证明或文件审计。** 达到行数上限仍会失败，不自动分页或忽略权限问题；接口上限未知时会警告。新旧 Raw 独立归档，不自动合并、去重或选取“最新版本”。本版没有每日调度器，无人值守仍受进程内凭证和服务持续运行限制。

### 触顶拆分与修复

新运行把行数触顶记为结构化 `row_limit` 原因。数据集卡片的“拆分触顶范围”只处理这些失败范围，**先生成新计划并显示新增请求数，再由用户确认**，不会在已经确认的运行中偷偷扩增请求。旧运行只有错误文本的失败不猜测原因，需重新执行得到标记或手工配置较小范围。

支持拆分的数据集遇到触顶时，保留该切片失败并继续其余**已确认**请求，最终运行仍标为失败，便于一次检查全部触顶范围。权限、Schema、网络重试耗尽等其他错误仍立即停止当前运行，不批量盲试无权限股票。自定义 API 的既有停止策略保持不变。

日频和分红的全市场单日请求按经过哈希校验的 L/D/P 股票池拆成单股请求，不假设接口支持逗号拼接多个代码。财务单股日期段对半拆为不重叠、连续的闭区间，可再次确认递归拆分。单股单日仍触顶时明确停止并提示人工核对，不伪造分页或覆盖成功。拆分请求允许个股停牌、未上市或无公告/报告返回空；混有未拆分日频请求时，全市场空响应仍失败。

拆分规则与实际股票代码在确认时持久化。后续全量、增量及补采使用当前叶子分区；父切片继续保持失败，其原始归档不变，不再重复计为当前未完成。旧父范围可在原运行中查阅。按股票拆分的范围固定为当次确认的池，不随新股票池自动扩大历史分区，成功只说明该池内请求完成。单计划最多 20,000 个请求，超限需缩小范围，不静默截掉一部分股票。

### 数据集组合与依赖阶段

预置采集页先展示数据集卡片，范围/依赖说明、近期查询和组合管理默认收起，避免挤占首屏；组合采集与管理位于卡片之后，并在折叠标题显示勾选数量。勾选多个数据集可保存命名组合，引用各自最新保存设置，不强制共用目录、起点或频率。组合有自己的全量、增量、补采策略与统一截止日。保存组合与检查计划不请求供应商；删除组合前须确认，且不会删除数据集设置、历史运行或 Raw 归档。

检查缺少或损坏的交易日历/股票池时，先展示依赖阶段的独立计划和精确请求数。确认后仅执行依赖；完成后点击“检查下一阶段 / 修复依赖”，重新检查本地证据并生成业务或依赖修复计划，仍须再次确认。已完成依赖阶段不会在后续被无意重复排入原选择。依赖失败不阻止另一独立依赖继续执行；可在主页进入下一轮检查。已确认下一阶段后，同一个父阶段不能再次提交分支；进度与入口重启后保留。

已有依赖时可直接检查业务组合。如果同时勾选刷新依赖，业务范围仍按检查时已有成功快照冻结，不自动吸收本组合内新股票；需要时在依赖更新完成后另查增量计划。每阶段最长确认期 30 分钟，合计最多 20,000 个请求。所有子计划先统一检查设置版本、覆盖与源证据，再原子创建批次和运行；任一计划失效则整阶段拒绝，不留下部分排队任务。零请求成员明确跳过，不创建空运行。单项失败后仍执行其他独立运行；主页展示各阶段、结果入口和组合补采入口。

## 自定义 API 配置与运行

1. 在“高级工具 → 自定义 API”选择股票列表、日线、每日指标或复权因子；“查找其他接口”可展开完整股票目录。
2. 设置查询范围、**绝对 Raw 保存目录**和空响应策略。逐日范围按自然日生成，不自动排除非交易日。
3. 点击“检查采集计划”。这一步保存配置并展示版本、范围、切片数、限流时间估算、目录和风险，**不发起 Tushare 请求**。“仅保存配置”也不会启动，保存后留在当前页面。
4. 确认摘要后点击“确认启动”。单任务入队时会在同一事务内再次检查配置版本和活动运行冲突；配置变化后必须重新检查。返回修改参数会使已检查计划失效。
5. 启动后直接显示本次进度、成功/失败/待处理切片、成功切片归档行数和目录。结束后可查看当前切片数据、导出成功切片，或按本次原固定配置续跑。请求参数、SHA256 和尝试记录位于“技术详情”。

检查页同时展示股票范围、日期、全部基础筛选条件和具体枚举值；较长的值可滚动查看，不省略确认范围。“查询拆分方式”只控制请求切片，不是一次性与定时模式。自定义 API 每次确认只启动一次采集；长期定时维护请使用“我的数据”中的数据需求。

SDK/HTTP、字段、JSON、枚举、频率、超时和重试默认置于“高级设置”。需要 JSON 的接口或草稿会自动展开；非默认设置会在检查页披露。浏览器草稿恢复仍保留，但刷新不会自动恢复可直接启动的确认计划，需要重新检查。“自定义 API”始终回到选数据，选择后使用新配置；“继续上次操作”可恢复新建前的编辑内容或结果，草稿仍保存在本浏览器。新建不会复用旧的可启动确认计划。

顶部持续显示执行线程、Token 配置、最近确认时间和服务连接状态。状态刷新超过 12 秒未完成时明确报错，不无限保留正常提示。线程停止、连接状态无法确认或缺少 Token 时，前端暂停启动和续跑，但仍可在服务可访问时保存配置、检查计划和查看归档。Token 已配置不表示权限有效；异常恢复后可重新检查服务状态。

“采集任务”保留已保存配置和历史结果。配置卡片的“检查并启动”进入同一个确认流程。“批量采集 / 任务组”按需展开批量工具，不作为首次采集的必经步骤。

Raw 根目录支持“选择目录”，也可手工输入绝对路径。原生目录选择目前仅适配 macOS；取消选择不修改输入内容。

股票列表、日线、每日指标、复权因子提供可视化参数表单和常用模板。日期输入自动转换为接口要求的 `YYYYMMDD`；逐日模板使用现有自然日切片，不自动识别交易日。模板只修改编辑器，保存与启动仍需明确操作。其他接口及无法无损表示的参数保留高级 JSON 模式。

编辑器按接口新任务、已保存任务分别保存浏览器本地草稿。切换接口或刷新页面后可恢复；草稿不等于 SQLite 配置，批量任务只读取已保存配置。“丢弃草稿并重置”恢复已保存版本或默认值。草稿按控制数据库隔离，不记录 Token 输入框；参数出现凭证字段时拒绝保存草稿。浏览器存储不可用时显示提示，并在离开未保存编辑内容前提醒。共用浏览器时注意本地草稿中的查询参数和目录信息。

### 批量拉取

保存多份接口任务，在“任务与运行”中勾选“加入批量”，或点击“全选可启动任务”，再点击“预览批量计划”。一次支持 1–102 个不同配置，合计最多 20,000 个请求切片。每个任务保留自己的 API、参数、切片、返回字段和 Raw 目录；不会把一套参数应用到所有接口。

提交前展示各任务的 API、配置版本、切片数、独立参数、字段、Raw 目录和限流时间估算。估算不含现有排队、网络和重试；SDK 计算入口不估算内部请求耗时。点击“确认并提交”时在同一入队事务中再次检查配置版本；配置被修改或出现活动运行时整批拒绝，需要重新预览。

勾选多个任务并输入组名，可“将勾选任务保存为组”。任务组持久化到 SQLite，保存成员与顺序，引用最新已保存配置，不冻结日期、不统一参数、不自动执行。选择任务组后点击“载入选中任务”，再预览并确认。删除任务组不会删除任务配置、运行或 Raw 数据。

所有配置先整体校验，再通过一个 SQLite 事务创建批次与独立运行。缺失配置、重复选择、活动运行冲突或超出切片限制时，整批拒绝，不留下部分提交。执行仍使用同一串行限流队列；一个任务失败后会继续其他任务。批次状态与各任务进度分别展示，失败任务可独立续跑。

### 数据预览与导出

结果页、运行列表和技术详情均可打开切片选择器。按日期、股票代码等请求参数文本查找，空格分隔的条件同时匹配；可组合状态和从 1 开始的切片序号，也可逐页查看全部切片，不限前 500 个。这是在筛选请求，不是筛选返回数据行。核对完整参数后自行选择切片；预览显示其序号、股票和日期等实际请求条件，不再自动打开第一个成功切片。

支持新 SDK Parquet、旧 SDK `dataframe.json` 和有效 HTTP JSON 表格。显示字段类型、总行数和分页，每页最多 200 行，不发起供应商请求。每次读取前校验登记的数据与元数据 SHA256；Parquet 分批读取所需行，JSON 预览限制为 64 MiB。超大 JSON 可导出后离线查看。

大整数和 Decimal 按字符串展示，避免浏览器精度损失；时间按 ISO 格式展示。失败但有有效表格的切片可以预览，但会明确显示失败原因，不能据此认为数据完整。

在预览窗口点击“导出当前切片”，或在已结束运行的详情中点击“导出本次运行的成功切片”，然后选择或输入绝对导出根目录。导出保存完整源文件及其元数据，不只保存预览页，不转换格式、不合并 Schema、不覆盖 Raw。整次运行只导出成功切片；未成功切片数量写入清单。

每次生成独立的 `<导出根目录>/tushare_exports/export-<UUID>/` 包，包含切片子目录和 `manifest.json`，记录来源、状态、文件哈希及跳过数量。导出成功后登记 SQLite，并记住该导出根目录；重复导出不会覆盖旧包。导出不能位于源切片目录内部。导出包不改变原运行的 Raw 引用，也不代表全市场覆盖。

导出支持两种布局，默认仍是“原始归档” (`raw`)。“后处理友好” (`organized`) 在同一导出包内按接口入口、请求选项和字段结构集中保存文件，**只整理副本路径，不合并、不去重、不转换格式**：

```text
export-<UUID>/
  daily--entry-27/
    variant-<请求选项SHA256>/
      schema-<字段结构SHA256>/
        data/trade_date=20261112__<slice_id>.parquet
        data/trade_date=20261113__<slice_id>.parquet
        metadata/<slice_id>.json
  manifest.json
```

同组 `data/` 只包含数据文件，可按该目录批量读取；原始元数据单独放在 `metadata/`。频度、复权、其他非日期/股票切片参数、请求字段、响应格式及成功/失败状态参与选项分组。不同字段顺序或类型分开；Parquet 复制并校验 SHA256 后读取实际字段结构进行分组，标注 `schema_status=verified_parquet`，若存在归档结构声明则必须一致，旧归档缺声明仍可读取真实结构。前复权 `pro_bar` 额外按股票及请求起止范围隔离，避免直接拼接不同复权锚点；两个 `pro_bar` 入口按各自 ID 分开。分组仍不保证主键唯一、价格序列连续或业务完整。

HTTP 和旧 JSON 保持原字节，不变成表格 JSON 或 Parquet。无字段结构声明时明确使用 `schema-unknown`，清单标注 `schema_status=unknown`；即使请求字段相同，也不代表实际 JSON 结构或类型兼容，需自行解析原响应。文件名仅用实际请求条件的短标签与完整切片标识，不代表返回数据覆盖，完整参数在清单和元数据中保留。

`POST /api/runs/{run_id}/export` 在原有 `destination`、可选 `slice_id` 外增加 `layout: "raw" | "organized"`（省略为 `raw`），返回值增加 `layout`，其余字段兼容。两种布局都导出完整文件，不受阅读页搜索、列选择或分页影响；整运行仍只导出成功切片，显式单切片可导出失败归档，状态和错误写入清单。清单版本为 2，包含分组路径、实际请求条件、来源、登记行数、归档声明行数、字段结构及每份数据/元数据哈希；不把重复登记行数当作唯一记录数。每次导出独立新包，不覆盖原归档或旧导出。任一校验或复制失败不发布半成品包。

日期切片按**自然日**生成 `YYYYMMDD`，不自动解释交易日历。包含非交易日时，根据接口含义明确选择是否允许空响应。历史分钟接口的时间参数需按官方格式手工填写；不把日期切片误认为分钟窗口切片。

例如日线任务：基础参数 `{}`，选择日期切片、`trade_date` 和日期范围；可再选择枚举参数 `ts_code`，填写 `["600000.SH","000001.SZ"]`。股票清单任务：基础参数 `{}`，枚举参数 `list_status`，值 `["L","D","P"]`。

自定义 SDK 财务接口同样按目录配置必填股票代码，不自动发现股票池；预置财务数据集则使用明确归档的本地股票池。两者都不擅自切换财务 VIP 接口。账号积分、单独授权及实时/分钟权限按 Tushare 实际响应执行。

## Raw 结构与语义

```text
<指定 Raw 根目录>/
  tushare/stocks/<分类>/<API>/<run_id>/<slice_id>/<attempt_id>/
    data.parquet     # SDK 返回 DataFrame，直接写入 Parquet
    response.json    # HTTP 模式：响应原始字节；与上面二选一
    meta.json
```

`meta.json` 保存脱敏参数、返回字段配置、请求/本地采集时间、接口文档、目录/采集器/SDK 版本、文件 SHA256 和捕获方式。SDK 归档还保存行数、Arrow Schema（字段名、类型、可空性）和 pandas 列类型。Token 不写入 SQLite 或 Raw；供应商响应或 DataFrame 若包含当前 Token，拒绝保存该数据并记录失败。

**SDK 快照不是 HTTP 原文。** SDK 模式将返回的 DataFrame 直接通过 PyArrow 写为 `data.parquet`，使用 Zstandard 压缩，不经过 JSON、不保存 pandas 索引、不清洗数据或转换单位。保留 DataFrame 的列类型、空值和浮点精度，但不能恢复 SDK 本身已经转换掉的原始类型。`wire_response_preserved=false`。HTTP 模式仍保留原始响应字节，`wire_response_preserved=true`。`pro_bar` 另有 `is_derived=true`。

新归档的 `archive_format_version=2`；`data_file/data_sha256` 指向实际数据文件，旧的 `response_file/response_sha256` 字段保留为兼容别名。SDK 捕获方式为 `sdk_dataframe_parquet` 或 `sdk_derived_dataframe_parquet`，HTTP 仍为 `http_response_bytes`。

已有 `dataframe.json` 及其元数据、哈希和运行记录保持不变，不自动迁移或覆盖。续跑可以跳过已验证的旧 JSON 切片，再把新切片保存为 Parquet；读取时应按实际文件路径和捕获方式区分格式。

SDK 1.4.29 未提供公开 HTTPS 地址设置接口；本项目仅对当前 `DataApi` 实例的地址改用对应官方 HTTPS 地址，不修改全局 `requests`、不使用代理、不写 SDK Token 文件。版本在依赖与锁文件中固定；升级 SDK 时须核对传输契约并重跑测试。

本版不统一代码、单位、复权或财务修订语义，不宣称 PIT，不发布研究数据。所有归档的 `coverage=not_proven`：执行成功只表示配置切片已获得有效返回并归档，不证明全市场完整性。

## 持久化、重试与恢复

SQLite 为 `data/collector.sqlite3`，保存配置及修订号、固定运行配置与接口目录规格、逐请求切片、每次尝试、批次及导出登记。预置数据集另存设置、确认计划、运行来源、分区与拆分映射、命名组合和分阶段计划，覆盖状态由对应切片和尝试记录计算。其底层配置不列入可编辑 API 任务，也不能绕过数据集计划直接启动。修改配置或刷新目录不改变已提交运行的接口规格与行数检查阈值。同一配置或同一数据集不允许同时存在多个排队/执行中的运行；同一时刻只执行一个运行，运行内部按线程配置并发执行请求切片。

网络错误、HTTP 429/5xx 和明确的短期频率错误可有限退避重试；权限、参数、Schema、疑似截断等错误立即失败。SDK 隐藏的业务返回码/HTTP 原文不能从 DataFrame 还原，错误按 SDK 异常记录。HTTP 失败响应在校验前归档；SDK 异常只保存诊断元数据，不伪造响应数据。

达到文档或用户设置的行数检查上限会阻断成功，不自动假设所有接口支持分页。请缩小范围、按代码/状态/交易所拆分，或按文档显式配置支持的 `offset/limit`。文档上限未知时需手动设置；低于阈值也不能证明供应商没有漏数。

停止服务时当前运行标为中断；异常退出后启动时也恢复为中断。**普通手工任务不自动续跑已中断运行**，已排队运行保留队列状态。仍获授权且未暂停的数据需求作业可在服务恢复后按冻结范围继续；发布后未登记结果的阶段会核对已有快照。手动续跑使用原固定配置，并先验证已成功切片的数据和元数据哈希；损坏证据阻断续跑。取消在当前网络请求返回后生效，已归档成功切片保留。

不要直接删除 Raw 或复制正在写入的 SQLite 主文件作为备份。运行历史仍引用原绝对 Raw 路径；移动目录需要单独设计迁移。自动回收默认关闭，仅在单独授权存储策略后释放通过安全检查的中间文件。

## 开发与检查

后端使用 FastAPI、官方 Tushare SDK、PyArrow、DuckDB 和 SQLite；前端使用 React 19、TypeScript、Tailwind CSS 和 Vite。前端开发依赖仅用于构建，不需要放入发布包。

```bash
uv sync --locked --extra dev
npm ci
uv run --locked python -m unittest discover -s tests -q
uv run --locked ruff check src scripts tests
npm run check
npm test
npm run build
```

`npm run build` 将资源输出到 `src/collector/static/`。修改界面后应提交对应构建产物，让只安装 Python 的使用者也能直接启动。`npm run dev` 在 `127.0.0.1:5173` 启动开发前端，将 `/api` 代理到 `127.0.0.1:7110`；另一个终端需要运行后端。普通使用时不需要执行这些前端开发命令。

测试使用临时目录和模拟供应商响应，不消耗真实积分。真实账号调用需由有效 Token 和对应权限另行验证。

显式刷新官方目录：

```bash
uv run --locked python scripts/refresh_catalog.py
```

该命令会访问官方文档并更新 `src/collector/catalog.json`，不拉业务数据、不启动任务。既有运行仍保留其固定参数；正式升级应核对目录差异、接口限制与 SDK 兼容性。
